## 2. 课程组织

课程结构严格参考 `ic-packaging.pigeon`：

```text
第N章 …
  第N.M节 …
    具体理论知识点卡片
    具体实验卡片
    具体工程卡片
```

- 章节标题统一为 `第N章 …`，顶部标签为 `第N章`。
- 小节标题统一为 `第N.M节 …`。
- 每个小节保留站点原生 `overview`，随后排列理论卡、实验卡和工程卡。
- 一个可独立学习的主题对应一张知识卡，不得把整个小节塞进一张“理论知识”卡。
- 禁止生成名为“理论知识”“讲课视频”“作业”的泛化知识卡。
- 禁止保留专门的作业章节或作业卡。
- 每个实验或工程活动独立成卡，位于该小节理论卡之后；侧栏使用原活动名称。
- 同一活动的所有原站 tab 必须保留在同一张卡中，名称、顺序和内容与原站一致。

## 3. 标题与理论正文原生化

原站蓝色大标题、Word/Axure 样式和其他原站视觉不得进入新课程：

- 与知识卡标题重复的正文大标题直接删除，由卡片头显示该标题。
- 页面顶层独立主题用于划分知识卡。
- 卡内编号型次级标题转换为站点原生 `numTitle`。
- 卡内说明型标题转换为站点原生 `boldCaption`。
- 禁止在课程数据中写死颜色、字体、边框、间距、圆角和固定像素宽度。
- 禁止把原站 class、style、蓝色标题样式或 CSS 复制进课程包。
- 标题、正文、列表、图片、图片组和表格必须全部转换为站点原生内容块。
- 理论知识卡中禁止使用 `html` 兜底。
- 解析器遇到未知或不支持的理论结构时，必须报告课程、小节、源文件、DOM 路径和原始片段并停止构建，不得转纯文本或回退 HTML。
- 正文首行缩进、标题字阶、段落间距、图片间距全部由站点公共样式控制。
- 原文文字逐字保留，不润色、不纠错、不补写；发现疑似错别字只在最终报告中提示。

## 4. 新增原生内容能力

以下能力必须写入 `docs/pigeon-format.md`，保持 `schemaVersion: 1` 的向后兼容扩展：

### 4.1 `tabSet`

- 通用结构：`{ type, id, tabs: [{ id, label, blocks }] }`。
- 理论/讲解视频和实验活动共用同一站点渲染器。
- tab 内继续使用站点原生 blocks，不得嵌入自定义视觉 HTML。
- 不允许嵌套 `tabSet`。
- 默认打开第一个 tab。
- 支持键盘、ARIA、焦点状态和移动端自动换行。
- tab 切换不得丢失已经填写的参数和练习状态。

### 4.2 `list`

- 支持有序和无序列表。
- 列表项保留 Span 富文本语义。
- 编号、缩进、间距和明暗主题由站点渲染。

### 4.3 `imageGroup`

- 记录图片、替代文本、可选说明和原始顺序。
- 宽屏由站点自动网格排列，窄屏自动单列。
- 课程数据不得指定固定像素布局。

### 4.4 扩展 `paramsTable`

- 继续兼容现有字符串单元格。
- 富单元格支持文本、图片、`rowspan`、`colspan` 和行/列表头语义。
- 课程数据只表达内容和表格语义，不表达视觉样式。
- 现有 `ic-packaging.pigeon` 无需迁移，视觉和行为不得回退。

## 5. 表格转换

所有原始表格必须先按语义分类：

- 静态数据表转换为站点原生 `paramsTable`。
- 参数选择答题表转换为站点原生 `paramSelect`。
- 工艺流程答题表转换为站点原生 `stepSimulation`。
- 仅用于排列图片或段落的布局表不得伪装成数据表，必须按阅读顺序拆成 `paragraph`、`image` 或 `imageGroup`。
- 禁止保留原站表格 HTML、固定列宽和原站表格样式。
- 表内图片、文本、单位、表头、合并关系和原始顺序必须完整保留。

响应式要求：

- 桌面端保留二维表格，方便扫描和比较。
- 容器不足时，静态宽表自动转成带列名的纵向记录。
- 合并单元格在窄屏中转换为分组标题或共享字段。
- 不得隐藏列、裁剪内容、截断图片或缩小到不可读。
- 所有课程卡片内禁止横向滚动。

## 6. 导航与知识卡状态

- 左侧目录层级为章节 → 小节 → 知识卡。
- 章节可折叠，同一时间只展开当前章节。
- 当前章节中的小节和知识卡目录全部显示，小节不再二次折叠。
- 顶部章节 tab 与侧栏章节状态同步。
- 窄屏使用同一目录树的抽屉，不维护第二套目录。
- 导航文字不得截断或产生横向滚动。
- 知识卡独立折叠，默认收起。
- 从目录定位知识点时，自动展开目标卡并滚动到卡片；其他已打开卡不强制关闭。
- 卡片展开状态只保存在当前浏览会话，不进入学习进度，也不同步到云端。

## 7. 视频组织

- 视频不得成为名为“讲课视频”的独立导航卡。
- 能由标题和正文证明关联的视频，放入对应知识卡的“讲解视频”tab。
- 无法可靠匹配的视频放到小节末尾“补充视频”卡。
- 视频名称、顺序、文件、海报和字幕必须保留原始来源映射。
- 视频和所有媒体必须离线包含在课程包中，不得访问原站 PHP 或外部 URL。

## 8. 选择题与测试组织

三门课程当前作业题数量：

- IC 制造：71 题
- IC 器件：85 题
- IC 封装：101 题
- 合计：257 题

选择题转换要求：

- `stem` 只包含题干。
- `options` 必须保存 `A. 完整正文`、`B. 完整正文` 等原始选项。
- 兼容换行、中文分号、英文分号和选项字母粘连等源格式。
- 选项字母和数量必须与原网页选择器逐项一致。
- 正确答案只能来自对应满分审计。
- 选项为空、只有字母、答案不存在或答案不在选项中时，构建硬停止。
- 保真门禁必须逐项检查题干和每一个选项。

题目归属要求：

- 建立版本化 `question-knowledge-map.json`。
- 每题记录题目 ID、原作业、源文件、目标知识点、题干关键词、正确答案关联、理论原文证据和匹配理由。
- 候选映射和理由可以由较低成本模型生成，但模型输出不能绕过证据门禁。
- 每题必须有直接理论原文证据；无证据、跨章、重复归属或未归属均硬停止。
- 每道作业题在全部知识点小测中恰好出现一次。
- 每道作业题在所属章节测试中恰好出现一次。
- 题目在 `questionBank` 中只定义一次，小测和章节测试仅引用 ID。
- 每个理论知识卡最后放置站点原生 `sectionQuiz`，组织方式与参考包一致。

## 9. 实验、工程与双层下拉

- 静态说明、参数矩阵、流程表、图片、视频和 tab 必须完整保留。
- 参数名称、所有选项、单位、合并分组和满分答案逐项来自原站证据。
- 双层流程题必须同时保留：
  - 上层“功能区/流程名”下拉及其选项、正确答案和独立计分。
  - 下层每一“具体工序”下拉及其选项、正确答案和独立计分。
  - 原始 `rowspan` 分组、子工序顺序、仿真按钮索引和视频映射。
- 桌面端使用紧凑的站点原生分组表。
- 移动端使用分组手风琴：组头保留上层下拉，内部显示全部子工序和仿真按钮。
- 不能把上层下拉当成纯装饰，也不能把两级答案合并成一个答案。
- 工程按钮若原站真实行为是返回结果图片，则继续显示经过验证的原始结果图片，不伪装为客户端绘图。

## 10. 绘图与 Canvas 仿真

- 绘图类题目必须参数驱动，能够正常显示和交互。
- 使用 `platform-runtime-preview` 的站点自有视觉与控件风格。
- 不允许固定演示曲线、静态截图冒充交互或直接运行原站 jQuery 页面。
- 必须重构移植原始参数、公式、坐标和绘图逻辑，形成独立离线 sandbox。
- 必须保留题名、提示、参数、选项、单位、阶段、公式、坐标轴、刻度、图例、初始状态和全部输出。
- 使用多组正确、错误和边界输入与原站输出对照，证明迁移逻辑等价。
- sandbox 只允许携带网格、尺寸约束和响应式布局 CSS。
- sandbox 的颜色、字体、圆角、边框和状态色必须调用站点注入的设计令牌。
- sandbox 不得访问父页面 DOM、登录状态、cookie、localStorage、原站 PHP 或外部网络。
- 对依赖服务端计算的页面，必须捕获所有有限输入组合的请求、响应、资源和哈希；证据不完整时硬停止，不猜测公式。

## 11. 样式硬约束

- 普通课程内容和公共组件全部调用 PigeonLib 设计系统与 `tokens.css`。
- 不在课程 JSON 中硬编码颜色、字体、间距、圆角或固定宽度。
- 不复制原站蓝色标题、表格、按钮和 tab 样式。
- 不引入 UI emoji，不增加装饰性竖线。
- 明暗主题下均需可读。
- 所有文本、图片、表格、tab、下拉和 Canvas 都必须限制在卡片宽度内。
- 页面必须满足 `document.documentElement.scrollWidth <= innerWidth`。

## 12. 分阶段交付与验收

第一阶段只制作黄金样板：原站 `0-1`“氧化”小节。样板必须覆盖：

- 两个以上具体理论知识卡。
- 小节 overview。
- 蓝色大标题去除与站点标题层级。
- 原生正文、列表、图片、表格和图片组。
- 讲解视频 tab。
- 作业题完整选项、语义映射和知识点小测。
- 实验 1 的全部 tab、参数表和 Canvas 温度曲线。
- 桌面和移动端无横向滚动。

黄金样板通过自动门禁后，必须提供：

- 本地可访问页面。
- 桌面和手机截图。
- 原站与新卡片结构对照。
- 复杂表格桌面/移动端重排对照。
- 至少两组参数产生不同 Canvas 输出的证据。
- 资源请求和控制台错误报告。

只有用户明确人工认可黄金样板后，才允许批量重建三门课程。

全量阶段采用：

- 自动遍历全部知识卡，检查资源、tab、表格、下拉、Canvas 和溢出。
- 人工每章分层抽查理论、复杂表格、视频、实验和工程各至少一例。
- 将现有 `ic-packaging.pigeon` 纳入回归测试，保证其视觉和行为不回退。

验收视口至少包括：

- 1440px 桌面。
- 1024px 平板/窄桌面。
- 390px 手机。
- 360px 窄手机。

## 15. 硬停止条件

发生以下任一情况时不得生成正式交付包：

- 正文、标题、列表、表格单元格、图片说明、题干、选项、参数或单位无法回溯到原始来源。
- 理论内容出现未原生化结构或回退 HTML。
- 原站样式、固定宽度、外链、PHP、登录态或网络依赖残留。
- 表格、图片、tab、下拉或仿真在任一验收视口横向溢出。
- 选择题选项为空、答案无证据或题目映射不唯一。
- 原站多 tab、双层下拉、合并关系、图片或视频信息缺失。
- Canvas 不随参数变化、输出为空或与原始逻辑不一致。
- 服务端仿真的有限输入输出证据不完整。
- `ic-packaging.pigeon` 回归测试出现视觉或行为退化。
