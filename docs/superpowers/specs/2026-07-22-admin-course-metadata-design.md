# 管理面板课程元数据管理设计

日期：2026-07-22

## 目标

管理员可在“全部课程”中管理服务端上传课程与内置课程的元数据，包括编辑标题、副标题、分类、发布人、作者和简介，以及删除课程。操作沿用现有管理面板视觉风格，并写入审计日志。

本次不编辑 `.pigeon` 内的章节、知识卡、题库或术语内容，也不改变课程包格式。

## 数据设计

### 服务端上传课程

继续以 `courses` 表为权威数据源。管理员编辑时直接更新允许的元数据字段；管理员删除时删除课程数据库记录，并删除 `server/data/courses/<courseId>/` 下的版本文件。

### 内置课程

内置课程仍以 `app/src/core/course-registry.js` 为离线默认值。服务端新增按 `course_key` 唯一存储的内置课程覆盖表，保存可选元数据覆盖值与隐藏标记。

- 编辑内置课程：写入或更新覆盖记录。
- 删除内置课程：写入隐藏标记，不删除随站点发布的静态 `.pigeon` 文件。
- 后端在线：管理页与首页将覆盖值合并到内置默认值，隐藏已删除课程。
- 后端离线：前端无法取得覆盖记录时，继续使用内置默认值，保证完整离线运行。

## API

管理端课程 API 增加：

- `PATCH /api/admin/courses/:ref`：校验并更新标题、副标题、分类、发布人、作者、简介。`ref` 明确区分服务端课程 ID 与内置课程 key。
- `DELETE /api/admin/courses/:ref`：删除服务端课程或隐藏内置课程。

公共课程响应附带内置课程覆盖列表，使首页无需新增独立请求即可合并在线元数据。分类必须来自现有 `COURSE_CATEGORIES`；文本字段去除首尾空白并设置合理长度上限；标题与发布人不能为空。

所有管理变更记录到 `audit_log`，新增“编辑课程”和“删除课程”动作标签。

## 管理界面

“全部课程”每行保留状态、发布人、分类和更新时间，并增加：

- “编辑”：打开复用现有遮罩层风格的课程编辑弹窗。
- “删除”：危险按钮，二次确认后执行；提交期间禁用按钮防止重复请求。
- “预览”“下架”：维持现有行为，仅在适用课程上显示。

编辑弹窗字段为标题、副标题、分类、发布人、作者、简介。采用现有 `admin-form`、`admin-select`、按钮、令牌和明暗主题；简介使用多行文本框。布局使用 flex/grid/gap，不新增绝对定位布局，不写死颜色，不使用 UI emoji 或装饰性竖线。

成功后关闭弹窗、显示 toast，并刷新全部课程与审计日志；失败时保留输入并在弹窗内显示服务端错误。

## 删除语义

- 服务端课程：删除数据库记录及其课程包目录，现有级联关系负责删除版本记录。
- 内置课程：仅在服务端写隐藏标记，静态课程包保留。
- 学习进度、评分、评论和书架记录按 `course_key` 独立存储，本次不主动清理，以避免误删用户数据；同 key 课程未来恢复时可继续关联。

## 验证标准

1. 管理员可编辑六项元数据，刷新页面后值保持不变。
2. 编辑结果在后端在线的首页课程卡片和详情中生效。
3. 管理员可删除上传课程，数据库记录和课程包目录均移除。
4. 管理员可删除内置课程，后端在线时管理页和首页不再显示；后端离线时默认内置课程仍可使用。
5. 非管理员无法调用新增 API；非法分类、空标题、空发布人和超长文本被拒绝。
6. 编辑和删除均产生审计日志，破坏性操作需要二次确认。
7. 管理页在 1377 x 812、窄屏、亮色和暗色主题下无溢出或重叠。
8. 服务端测试、前端生产构建和浏览器交互验证通过。
